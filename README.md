# Хуки Claude Code: 3 безопасных примера на русском

Три собственных хука Claude Code: защита выбранной папки, проверка JSON после правки и журнал локальной проверки.
Для тех, кто хочет разобраться с хуками на маленьких примерах и проверить их без подписки.

## Быстрый старт за 1 минуту

Нужен Python 3.9+ на macOS или Linux. Откройте терминал в папке скачанного проекта:

```bash
python3 -B examples/demo.py
python3 -B -m unittest discover -s tests -v
```

Демо покажет шесть результатов: разрешенную и запрещенную запись, правильный и сломанный JSON, успешную и неуспешную проверку перед записью журнала. Затем пройдут 22 теста. Claude Code, ключи и сеть для этого не нужны. Временные файлы создаются внутри `.test-tmp/` и убираются самим демо.

## Какие события есть

Хук - обычный скрипт, который Claude Code запускает при выбранном событии. Он получает JSON через стандартный ввод.

| Событие | Когда срабатывает | Для чего подходит |
| --- | --- | --- |
| `PreToolUse` | Перед вызовом инструмента | Остановить нежелательную правку |
| `PostToolUse` | После успешного вызова | Проверить уже измененный файл |
| `PostToolUseFailure` | После ошибки инструмента | Обработать неудачный вызов |
| `PermissionRequest` | При запросе разрешения | Дополнить обработку разрешений |
| `UserPromptSubmit` | При отправке задания | Проверить входное задание |
| `SessionStart`, `SessionEnd` | При начале и завершении сессии | Подготовка и завершение работы |
| `SubagentStart`, `SubagentStop` | При запуске и завершении подагента | Проверка отдельной работы |
| `Stop` | Когда Claude заканчивает ответ | Проверка перед завершением |
| `StopFailure` | Когда ход завершился ошибкой API | Обработка ошибки API |

Это основные события для начала. В справке есть также события конфигурации, файлов, задач, worktree, MCP-запросов и другие. Полный список - в [официальной документации хуков](https://code.claude.com/docs/en/hooks). События `OnFailure` в прочитанной справке нет: ошибка инструмента называется `PostToolUseFailure`.

## Триггеры трех примеров

Все три настройки лежат в [.claude/settings.json](.claude/settings.json). `matcher: "Write|Edit"` выбирает инструменты записи и редактирования.

| Скрипт | Событие | Проверка | Результат отказа |
| --- | --- | --- | --- |
| [protect_folder.py](hooks/protect_folder.py) | `PreToolUse` | Путь не входит в `protected/` | Код 2 запрещает действие |
| [check_json.py](hooks/check_json.py) | `PostToolUse` | Файл `.json` разбирается как JSON | Код 2 сообщает ошибку Claude |
| [record_check.py](hooks/record_check.py) | `PostToolUse` | Текст заканчивается переводом строки | Результат `fail` попадает в журнал, код 2 сообщает ошибку |

`PostToolUse` срабатывает после записи. Ошибка такой проверки не отменяет правку и не восстанавливает прежний файл.

## Один пример настройки и тест отказа

Эта часть `settings.json` запрещает правки папки `protected/`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -B \"${CLAUDE_PROJECT_DIR}/hooks/protect_folder.py\" --protected protected",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

В [фикстуре отказа](fixtures/guard-deny.json) указана запись `protected/keep.json`. Проигрыватель переводит относительные пути фикстур в абсолютные пути временного проекта, как во входе Claude Code. В выводе демо будет:

```text
guard-allow: exit=0 (действие разрешено)
guard-deny: exit=2 (действие запрещено)
```

Полный ожидаемый вывод - [expected-demo.txt](fixtures/expected-demo.txt). Тесты отдельно проверяют `Write`, `Edit`, переход через `..`, похожее имя `protected-copy` и символическую ссылку в защищенную папку.

## Как включить и отключить

1. Сначала запустите демо и тесты.
2. Для пробы запустите Claude Code из корня этого репозитория и подтвердите доверие к проекту. Для собственного проекта перенесите папку `hooks/`, а записи из `.claude/settings.json` добавьте к существующим настройкам. Сохраните прежние настройки перед правкой.
3. Укажите нужную папку в аргументе `--protected`. Путь задается относительно корня проекта. При переносе скриптов измените пути в настройках.
4. Перезапустите Claude Code. Проверьте правила через `/hooks`: попробуйте Write/Edit в обычной и защищенной папке.
5. Для отключения уберите только три добавленные записи из `hooks` в настройках проекта и перезапустите Claude Code. Другие настройки сохраняйте.

Для живого подключения нужен установленный и настроенный Claude Code. Бесплатный прогон скриптов от него не зависит. Этот репозиторий сам не меняет ваши пользовательские настройки.

## Что записывается в журнал

`record_check.py` проверяет UTF-8 файлы `.txt`, `.md`, `.py`, `.json` до 1 МиБ. Пустой файл допускается. В `.local-checks/results.jsonl` он добавляет время UTC, относительный путь, имя проверки `final_newline` и статус `pass` или `fail`. Содержимое файлов, задания и ответы Claude в журнал не попадают. Сам путь файла может содержать чувствительное название - журнал остается локальным и исключен из Git.

Скрипт не запускает команды из входного JSON и не отправляет данные. Каталог и файл журнала не должны быть ссылками. Журнал растет при запусках; автоматической очистки и ротации здесь нет.

## Версия и ограничения

Формат сверялся 24.10.2026 с [первоисточником Claude Code](https://code.claude.com/docs/en/hooks). Версия установленного CLI - **2.1.309**, такая же версия указана в [релизе Anthropic](https://github.com/anthropics/claude-code/releases/tag/v2.1.309). Проверялся запуск скриптов и команд из настроек на искусственных событиях. Живая сессия Claude Code не запускалась.

- Защита относится к Write/Edit. Bash, NotebookEdit, MCP и сторонние процессы она не ограничивает. Это учебный пример, не изоляция от вредоносного кода.
- Путь за пределами начального проекта отклоняется. Для отдельного worktree запускайте отдельную сессию из его корня: `CLAUDE_PROJECT_DIR` остается корнем исходной сессии.
- Проверка JSON проверяет синтаксис, без схемы и автоисправления. Файлы больше 1 МиБ явно отклоняются.
- Ошибочный вход возвращает код 2. Изменение исходных файлов не выполняется; запись ведется только в локальный журнал и временные папки демо/тестов.
- Настройки рассчитаны на macOS/Linux. Windows shell и PowerShell в этом наборе не поддержаны.
